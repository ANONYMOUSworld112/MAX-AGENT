## 2. Active Coding Implementation: `actions/dev_agent.py`

When the user asks MAX to *"Build a Python project"* or *"Create a calculator"*, the system executes `actions/dev_agent.py:dev_agent()`.  
The actual workflow proceeds as follows:

```
User Input ("Build a Python expense tracker")
 ↓
main.py:_execute_tool(name="dev_agent", args={...})
 ↓ Dispatched via loop.run_in_executor
actions/dev_agent.py:dev_agent()
 ↓
Step 1: _plan_project()
 │  Calls Gemini Flash to generate a JSON file plan.
 │  Files are listed in dependency order.
 ↓
Step 2: Project Directory Created
 │  Created under ~/Desktop/MaxProjects/<project_name>
 ↓
Step 3: Sequential File Generation (_write_file)
 │  Iterates through planned files.
 │  For each file: calls Gemini Flash to generate full source code.
 │  Writes code directly to disk at <project_dir>/<file_path>.
 ↓
Step 4: Dependency Installation (_install_dependencies)
 │  Checks each planned dependency via: sys.executable -m pip show <pkg>
 │  If missing: executes subprocess.run([sys.executable, "-m", "pip", "install", dep])
 │  ──► DIRECTLY ON THE HOST PYTHON ENVIRONMENT!
 ↓
Step 5: Test / Execution Verification (_test_project)
 │  Runs entry point via: subprocess.run([sys.executable, entry_point], timeout=20)
 │  Captures stdout / stderr.
 ↓
Step 6: Iterative Fix Loop (Up to 5 attempts)
 │  If traceback detected: calls _fix_error() with failing code + traceback.
 │  Overwrites failing file and re-executes.
 ↓
Returns summary string to main.py
```

## 3. Critical Security & Engineering Deficiencies

### 1. Host Environment Contamination (Unsandboxed `pip install`)
In `actions/dev_agent.py:255`:
```python
result = subprocess.run(
    [sys.executable, "-m", "pip", "install", dep],
    capture_output=True, text=True, cwd=str(project_dir)
)
```
- `sys.executable` points to the active Python interpreter running MAX itself!
- Package names generated by Gemini Flash are installed **directly into the host environment** without a virtual environment (`venv`).
- **Supply-Chain Squatting Risk**: LLMs frequently hallucinate plausible-sounding package names (e.g. `python-request-helper`). Attackers register these hallucinated names on PyPI with malicious post-install hooks. Running unsandboxed `pip install` allows arbitrary code execution with the host user's privileges.

### 2. Missing Scope and Path Checks
- Files are written based on relative paths returned in the LLM's JSON plan (`full_path = project_dir / file_path`).
- If the LLM generates a path traversal (`../../../../Windows/System32/evil.py`), `dev_agent` does not validate that `full_path.resolve()` remains inside `project_dir`.

### 3. Absence of Git Isolation
- Code is written directly into `~/Desktop/MaxProjects/`.
- There is no dedicated git worktree, no feature branch, no initial commit, and no rollback checkpoint.
- If a generation fails midway or produces broken code, prior file state is lost.

### 4. Flawed Test Integrity
- `_test_project()` merely executes `python main.py` with a 20-second timeout.
- It considers the test a SUCCESS if `exit_code == 0` and no traceback is in stderr.
- It does **not run pytest**, does not assert test coverage, and does not check for test weakening or assertions.

## 4. Required Evolution (Master Spec Section 22)

1. **Provider-Agnostic `CodingExecutor` Abstraction**:
   - MAX must not be hardcoded to an unverified internal loop.
   - Define `CodingExecutor` interface with implementations: `OpenCodeWorker`, `CodexWorker`, `ClaudeCodeWorker`, `LocalAgent`.
2. **Strict Sandboxed Execution**:
   - Dedicated git worktree created for each coding task (`git worktree add`).
   - Isolated ephemeral virtual environment (`python -m venv .venv`).
   - Pinned dependencies with checksum verification before installation.
3. **Scope and Secrets Check**:
   - Verify `git status` after execution: zero files modified outside the workspace root.
   - Run secrets scan across diff (detect accidentally generated API keys or credentials).
4. **Test Integrity Verification**:
   - Execute pytest with assertions.
   - Ensure existing tests are not deleted or weakened.
